# SMU — Совет молодых ученых

Единая цифровая платформа научного сообщества Актюбинской области. Проект
строится на Next.js, TypeScript и Supabase. Публичный сайт, личный кабинет и
SMU Admin используют одну доменную модель и одну базу данных.

## Реализованные этапы

Реализована первая foundation-итерация:

- отдельный admin layout на `/admin`;
- Supabase Auth и разделенные browser/server/service-role клиенты;
- серверный RBAC/permissions layer;
- миграция `profiles`, `roles`, `permissions`, `user_roles`,
  `role_permissions`, `audit_logs`;
- RLS-политики и безопасный системный seed;
- экран входа и безопасное setup-состояние до подключения Supabase.

Медиа-библиотека:

- `media_assets` и `media_usages` с RLS и soft delete;
- восемь Storage buckets из архитектуры с ограничениями типа и размера;
- двухшаговая загрузка изображений через краткоживущий signed upload token;
- повторная серверная проверка фактического MIME-типа и размера;
- поиск, фильтры, превью и отображение связей файла;
- редактирование RU/KK alt-текстов, подписей, авторства и источника;
- audit log для загрузки, изменения метаданных и удаления.

Редакционный модуль:

- `articles` и обязательные RU/KK-записи в `article_translations`;
- двуязычные категории и теги, связь статей с медиатекой;
- статусы `draft`, `in_review`, `approved`, `published`, `archived`;
- контролируемые RBAC-переходы между редакционными статусами;
- создание, поиск, фильтрация, редактирование и soft delete статей;
- RLS: анонимный доступ только к опубликованным материалам;
- audit log для создания, редактирования, статусов и удаления.

Публичный Журнал СМУ:

- двуязычный каталог материалов с переключением RU/KK;
- поиск и фильтры по категориям и тематическим тегам;
- адаптивные карточки, обложки из публичной медиатеки и empty states;
- публичные страницы статей с безопасным текстовым рендерингом;
- динамические SEO и Open Graph-метаданные;
- жёсткая серверная фильтрация статуса `published`, не зависящая от сессии;
- главная страница проекта перенаправляет в публичный журнал.

Профили учёных и каталог научного сообщества:

- отдельные двуязычные профили исследователей с RU/KK slug и биографией;
- организации и научные направления как управляемые справочники;
- аватары из централизованной медиатеки, ORCID, научные ссылки и публичные контакты;
- административное создание, редактирование, soft delete и аудит изменений;
- верификация профилей с автоматическим возвратом в черновики после редактирования;
- публичный каталог с поиском и фильтрами по организации и направлению;
- локализованные страницы учёных с динамическими SEO и Open Graph-метаданными;
- RLS: анонимный доступ только к верифицированным профилям.

Исследования и научные проекты:

- отдельные разделы админки и публичные каталоги на `/research` и `/projects`;
- общий паспорт работы и обязательные RU/KK-описания, цели и результаты;
- организации, научные направления и команды из верифицированных профилей;
- этапы `planned`, `active`, `completed`, сроки, DOI и научные ссылки;
- статусы `draft`, `published`, `archived`, soft delete и централизованные обложки;
- раздельные права `research.manage` и `projects.manage`;
- транзакционное сохранение содержания, связей, возврата в черновики и аудита;
- RLS и дополнительная серверная фильтрация только опубликованных записей;
- поиск и фильтры по организации, направлению и этапу работы;
- локализованные страницы с SEO, Open Graph и ссылками на языковые версии.

## Локальный запуск

1. Скопируйте `.env.example` в `.env.local` и заполните
   `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   (ключ `sb_publishable_...`) и серверный `SUPABASE_SERVICE_ROLE_KEY`.
   Старый `NEXT_PUBLIC_SUPABASE_ANON_KEY` поддерживается как запасной вариант;
   если заполнены оба публичных ключа, используется publishable key.
2. Примените миграции из `supabase/migrations` по порядку.
3. Выполните `supabase/seed.sql`.
4. Создайте пользователя через Supabase Auth и один раз назначьте ему роль
   `super_admin` через SQL Editor:

```sql
insert into public.user_roles (user_id, role_id)
select '<auth-user-id>', id
from public.roles
where code = 'super_admin';
```

5. Запустите `npm run dev` и откройте `/admin`.

## Проверки

```text
npm run lint
npm run typecheck
npm run test
npm run build
```

Тесты SQL используют PostgreSQL в памяти (PGlite), применяют все миграции и seed,
проверяют RLS, права RPC, откат конфликтующих правок и soft delete. В тестовой
среде воспроизводятся платформенные схемы Auth/Storage без подключения к внешней базе.

Для обновления существующего Supabase-проекта примените
`supabase/migrations/005_science_works.sql`.

После подключения проекта Supabase типы базы следует генерировать в
`src/types/database.types.ts` после каждого изменения схемы:

```text
npx supabase gen types typescript --project-id <project-id> > src/types/database.types.ts
```

Следующая итерация: наставничество.
